# 30 дней в движении — инструкция по запуску

Всё делается в браузере, без консоли. Деплой Worker'а — через подключение GitHub-репозитория к Cloudflare (как ты деплоишь GitHub Pages).

## 1. Создать репозиторий на GitHub

1. github.com → **New repository** → назови, например `move-challenge-bot`
2. Загрузи туда все файлы из этого пакета, сохранив структуру папок:
   ```
   move-challenge-bot/
     src/index.js
     wrangler.toml
     schema.sql          (не деплоится, просто хранится в репо для справки)
     apps-script.gs       (тоже просто для справки)
   ```
   Через веб-интерфейс GitHub: **Add file → Upload files**, перетащи файлы. Для `src/index.js` сначала создай папку `src` (просто набери `src/index.js` в поле имени файла при загрузке — GitHub сам создаст папку).

## 2. Создать D1-базу данных

1. dash.cloudflare.com → **Workers & Pages** → **D1 SQL Database** → **Create Database** → назови `move-challenge-db`
2. Открой созданную базу → вкладка **Console** → вставь содержимое файла `schema.sql` целиком → **Execute**. Это создаст три таблицы.
3. На странице базы найди **Database ID** (длинная строка вида `xxxxxxxx-xxxx-...`) — скопируй её.
4. Вернись в свой GitHub-репозиторий, открой `wrangler.toml`, замени `ВСТАВЬ_СЮДА_ID_БАЗЫ` на скопированный ID, сохрани (commit).

## 3. Подключить репозиторий к Cloudflare Workers

1. dash.cloudflare.com → **Workers & Pages** → **Create** → вкладка **Workers** → **Import a repository** (или «Connect to Git»)
2. Авторизуй Cloudflare в GitHub, выбери репозиторий `move-challenge-bot`
3. Cloudflare сам увидит `wrangler.toml` и настроит билд — просто нажми **Deploy**
4. После деплоя открой Worker → **Settings → Variables and Secrets** → добавь:
   - `BOT_TOKEN` (тип **Secret**) — токен от BotFather
   - `SHEETS_WEBHOOK_URL` (обычная переменная) — заполнишь на шаге 5

## 4. Прописать вебхук Telegram

Открой в браузере (замени на свой домен воркера, он будет вида `move-challenge-bot.твой-поддомен.workers.dev`):

```
https://move-challenge-bot.твой-поддомен.workers.dev/setup-webhook
```

Должен прийти ответ `"ok": true`. Всё, бот подключен — напиши ему `/start` в Telegram и проверь.

## 5. Google Sheets для модерации

1. Создай новую Google Таблицу
2. **Расширения → Apps Script** → вставь код из `apps-script.gs`
3. **Deploy → New deployment → Web app**:
   - Execute as: **Me**
   - Who has access: **Anyone**
4. Скопируй URL веб-приложения, вставь его как `SHEETS_WEBHOOK_URL` в настройках Worker'а (шаг 3.4)
5. Теперь каждая заявка сотрудника будет падать строкой в таблицу со ссылкой на скриншот — там же вручную меняешь статус pending → approved/rejected. (Учёт в дашборде считает approved + pending; если нужно, чтобы дашборд учитывал только approved — скажи, поправлю фильтр в `/stats`.)

## 6. Дашборд на GitHub Pages

1. В `dashboard/index.html` замени:
   - `STATS_URL` на реальный адрес `https://твой-воркер.workers.dev/stats`
   - `GOAL_POINTS` на общую цель по баллам (виртуальный маршрут)
2. Залей `dashboard/index.html` в отдельный репозиторий (или в этот же, в папку `docs/`) и включи GitHub Pages — так же, как делал с allrunrus.ru

---

## Как это работает для сотрудника

1. Пишет боту `/steps`
2. Бот пошагово спрашивает: шаги → минуты тренировки → был ли вместе с коллегой → был ли на встрече комьюнити → просит скриншот
3. Присылает скрин — бот сразу считает баллы и присылает разбивку
4. Заявка падает в Google Sheet на модерацию и сразу учитывается в `/stats` для дашборда (как pending)

**Важно:** город спрашивается один раз и запоминается. Если нужно изменить — напиши, добавлю команду `/city` для смены.
