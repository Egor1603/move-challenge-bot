# Как внести пробежку в бот

1. Напиши боту `/run` (или нажми кнопку **🏃 Новая пробежка**)
2. Если бот пишет тебе впервые — сначала спросит **имя и фамилию** и **город** (один раз, дальше не спрашивает)
3. Если сейчас **до 12:00 по твоему местному времени** — бот спросит, за какой день пробежка: **«Сегодня, {дата}»** или **«Вчера, {дата}»** (на кнопках сразу видны реальные числа, ошибиться сложно). После 12:00 бот сам берёт сегодняшний день — вопрос не задаёт
4. Дальше по порядку:
   - **Сколько километров** — можно с дробной частью (например, `5.4`)
   - **Был ли совместный бег с коллегой** — Да/Нет (для статистики, на баллы не влияет)
   - **Была ли встреча/тренировка спортивного комьюнити** — Да/Нет (даёт +2000 баллов, но не чаще раза в неделю)
   - **Скриншот трекера** — пришли фото
5. Бот сразу считает баллы и присылает разбивку, а следом — топ-10 по баллам и топ-10 по километрам

**Если за выбранный день уже есть запись** — бот не перезапишет её и не создаст вторую. Вместо этого пришлёт предупреждение с данными существующей записи. Если это ошибка (например, нужно исправить цифры) — писать администратору челленджа напрямую, через бот исправить нельзя.

**Кнопка 📊 Мой рейтинг** — показывает твоё место в общем зачёте по баллам и по километрам в любой момент, без необходимости вносить новую пробежку.

# История изменений по итерациям

**Итерация 1 — MVP.** Собран Telegram-бот на Cloudflare Workers + D1, диалоговый сценарий (шаги → тренировка → совместная активность → комьюнити → фото), синхронизация с Google Sheets для модерации, дашборд на GitHub Pages.

**Итерация 2 — упрощение механики.** Убран отдельный вопрос про минуты тренировки — оставлены только шаги и бонусы.

**Итерация 3 — переход на километры.** Метрика "шаги" заменена на "километры" с поддержкой дробных значений, формула баллов пересчитана (1 км = 100 баллов), терминология в диалоге сменилась на "бег".

**Итерация 4 — идентификация участников.** Добавлен явный вопрос "Имя и Фамилия" при первом обращении (вместо автоматического имени из Telegram-профиля), чтобы в рейтинге отображались реальные ФИО.

**Итерация 5 — UX-доработки.** Добавлены кнопки постоянного меню («Новая пробежка», «Мой рейтинг»), команда `/run` как основная (алиас `/steps` сохранён для обратной совместимости), после каждой пробежки бот присылает топ-10 по баллам и топ-10 по километрам.

**Итерация 6 — фикс критического бага сохранения.** Обнаружена и исправлена ошибка в SQL-запросе (недостающий placeholder для `points`), из-за которой сохранение пробежки после отправки фото падало с ошибкой.

**Итерация 7 — дашборд.** Дизайн переоформлен под фирменный стиль Точки (фиолетовая палитра, рукописный акцентный шрифт), добавлен рейтинг по километрам, позже — полная таблица всех участников; добавлен фавикон; убран абстрактный прогресс-бар.

**Итерация 8 — пересмотр баллов за совместную активность.** Бонус +1000 баллов за совместный бег с коллегой отменён (вопрос в диалоге остался для статистики, но на баллы больше не влияет).

**Итерация 9 — автоматические напоминания.** Добавлена cron-задача (ежедневно в 12:00 по Екатеринбургу), которая находит участников без активности 5+ дней и шлёт напоминание — с разными текстами для тех, кто уже бегал раньше, и для тех, кто прошёл регистрацию, но ни разу не отправил пробежку.

**Итерация 10 — часовые пояса и защита от потери данных.** Обнаружена проблема: бот считал "сегодня" по единому часовому поясу (Екатеринбург), из-за чего у участников из других городов пробежки записывались не на ту дату, а повторная отправка в тот же день молча перезаписывала предыдущую запись. Исправлено:
- дата определяется по часовому поясу **города участника** (справочник основных городов РФ, для неизвестных — Екатеринбург по умолчанию);
- если сообщение пришло **до 12:00 по местному времени** — бот явно спрашивает "Сегодня, {число}" или "Вчера, {число}" с реальными датами на кнопках; после 12:00 вопрос не задаётся, дата берётся автоматически;
- повторная попытка внести пробежку за уже существующий день **больше не перезаписывает** прошлую запись — бот показывает предупреждение с данными существующей записи и не сохраняет новую.
